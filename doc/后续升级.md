先看下工程当前的依赖全貌，再给出具体要动的清单：


本机有 JDK 8/17/21（没有 11），可行的目标是 **AGP 7.4.2 + Gradle 7.6.x + JDK 17** 这条线。要吃到 `repeatOnLifecycle`（lifecycle ≥2.4），牵一发动全身，完整清单如下：

## 一、工具链（必须动，连锁源头）

| 项 | 现在 | 目标 | 原因 |
|---|---|---|---|
| Gradle wrapper | 6.7.1 | **7.6.4** | AGP 7.4 要求 Gradle ≥7.5；7.6 才稳支持 JDK17 |
| AGP（根 build.gradle classpath） | 4.2.2 | **7.4.2** | lifecycle 2.5.x 要求 compileSdk ≥32，AGP 4.2 最高只支持 compileSdk 30 |
| 构建 JDK | 强制 JDK 8 | **JDK 17** | AGP 7.x 要求 JDK ≥11；之前 17 报错是"17 + 旧 AGP4.2/Gradle6.7"的组合病，换 AGP7.4 即可 |
| Kotlin | 1.4.21 | **1.7.20**（不能 1.8+） | 1.8.0 起 **`kotlin-android-extensions`（synthetic）插件被彻底移除**，全项目的 `kotlinx.android.synthetic` 引用会编译失败；1.7.20 还能带着这个插件跑（仅警告） |
| gradle.properties | `-Xmx1536m` | `-Xmx4096m` 左右 | AGP 7 更吃内存 |

## 二、android 配置（config.gradle）

- `compileSdkVersion: 30 → 33`、`buildToolsVersion → "33.0.2"`（lifecycle 2.5.1 要求 minCompileSdk 32；34 会逼你上 AGP 8，而 AGP 8 强制 namespace + JDK 17 全家桶，改动更大，所以选 33 配 lifecycle **2.5.1** 而不是 2.6.2）
- `targetSdkVersion: 30 → 33`（可选；但会引入行为变更，如通知权限、导出属性，建议这次**先不动**）
- `minSdk 26` 不变

## 三、依赖显式上抬

```gradle
// app/build.gradle 需要动/新增的
implementation 'androidx.lifecycle:lifecycle-runtime-ktx:2.5.1'   // 本次目标 API
implementation 'androidx.appcompat:appcompat:1.4.2'                // 现在被 base-core 锁在 1.2.0
implementation 'com.google.android.material:material:1.7.0'        // 1.3.0 不兼容新 core
implementation 'androidx.core:core-ktx:1.9.0'                      // appcompat 1.4+ 需要
implementation "androidx.room:room-runtime:2.4.3"                  // 2.2.5 与新 lifecycle 搭有兼容风险
kapt "androidx.room:room-compiler:2.4.3"                           // 对应 config.gradle roomVersion
// multidex 可直接删除：minSdk 26 本来就不需要
```

lifecycle 2.5.1 会传递拉起 **coroutines 1.6.x**（现在是 1.3/1.4 时代），这带来代码级改动，见下。

## 四、代码必须同步适配的点

1. **coroutines 1.6 移除了 `Flow.collect{}` 扩展函数**：`SectorFlowActivity` / `UsStockActivity` / `FundListActivity2` 里的 `import kotlinx.coroutines.flow.collect` 会变成 unresolved reference，要删掉这行 import（`collect { }` 本身还能用）。
2. `kotlin-android-extensions` 保持可用（Kotlin 1.7.20），synthetic 一行不用改；但想根治就得上 ViewBinding——那是另一个工作量。
3. manifest 的 `package` 属性 AGP 7.4 仍支持，不用动（AGP 8 才强制 namespace）。
4. **base-core/base-core-ktx 2.6.0**（jitpack 老库）：Gradle 冲突解析取最高版本，不会挡升级，但它传递带的 appcompat/lifecycle/autodispose 旧用法在新版本之上要做**全页面回归测试**（启动页、日志、网络封装等都出自它）。

## 五、还有一个现实前提

现在都是 `--offline` 编译，上面 AGP 7.4.2、Gradle 7.6.4 发行包、Kotlin 1.7.20、lifecycle 2.5.1、material 1.7.0 等**本地缓存都没有**，需要先联网拉一轮。

## 建议

这一圈下来的本质是：**为了一个 API（repeatOnLifecycle），做的是一次整个工程的技术栈升级（工具链 + AndroidX + 协程 + 全量回归）**，收益和风险完全不成比例。当前阶段维持 `launchWhenResumed`（它正是 lifecycle 官方在 2.2~2.3 时代给出的对应方案，语义就是我们需要的"RESUMED 后才消费"）；把上面这份清单当作日后专项升级的路线图，真做的时候一步到位到 AGP 7.4/compileSdk 33/Kotlin 1.7.20 这条线，顺便换掉 synthetic→ViewBinding。需要的话我可以把这份升级清单落成文档放进工程里。
